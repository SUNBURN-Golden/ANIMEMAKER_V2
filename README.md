# AnimeMaker V2 – 손그림 애니메이션 뮤직비디오 제작기 (Windows)

**노래와 가사**를 올리면, 이미 구독 중인 AI(ChatGPT · SuperGrok · Google AI(Gemini) · Claude)가 이야기를 쓰고 그림을 그리고,
내 PC 가 그 그림들을 **한 장씩 넘겨서** 옛날 손그림 애니메이션(80~90년대 극장 애니, 지브리·디즈니 감성) 같은 뮤직비디오를 만들어 주는 윈도우 프로그램입니다.
주인공은 **캐릭터 파일**로 꽉 고정해서, 같은 주인공이 나오는 **에피소드형 뮤직비디오**를 계속 이어 만들 수 있어요.

> 이 프로그램은 **AnimeMaker V1** 에서 갈라져 나온 새 버전이에요. V1 은 영상 AI 로 클립을 만들었다면, V2 는 그림을 이어 보여 주는 셀 애니메이션 방식이에요.
> V1 과 **따로 설치**되고(이름 `AnimeMaker V2`), 설정과 작업 폴더도 따로 써요(`문서\AnimeMaker V2`). 두 프로그램을 같이 써도 서로 건드리지 않아요.

> 🔒 **구독 전용**: API 키(쓴 만큼 돈이 나가는 종량제)를 쓰지 않습니다. 각 회사의 공식 프로그램(CLI)에 **구독 계정으로 로그인**해서 쓰고,
> 실행할 때 API 키 환경변수를 자동으로 지워 실수로 과금되는 일을 막습니다. 사용 한도에 걸리면 기다렸다가 이어서 합니다.

## 어떤 영상이 나오나요?

- **움직이는 장면 (지브리식, 기본)**: 노래의 40~50% (후렴·신나는 마디)는 AI 가 **1초에 6~8장**씩 열쇠 그림을 그리고, 그 사이 그림은 **내 PC 가 무료로** 만들어서 2프레임마다 넘겨요. 손으로 그린 극장 애니처럼 부드럽게 움직여요.
- **멈춘 장면**: 나머지는 그림 1~4장을 길게 보여 주면서 카메라가 천천히 훑거나(팬) 다가가요(줌·트럭). 조용하고 영화 같은 느낌.
- **배경과 인물을 따로 (멀티플레인)**: 컷마다 배경 판 1장 + 인물 셀(인물만, 초록 배경 → PC 가 배경을 빼서 투명하게)을 겹쳐요. 카메라가 움직이면 배경이 인물보다 조금 덜 움직여서(0.8배) 깊이감이 생겨요.
- **손그림 필름 느낌**: 2프레임마다 아주 살짝 흔들리는 그림(라인 보일), 필름 입자, 따뜻한 색, 가장자리 어둡게(비네트), 종이 질감 — 모두 켜고 끌 수 있어요.
- **자막은 나중에**: 먼저 자막 없는 깨끗한 원본을 만들고, 그 위에 가사 자막을 따로 입혀요. 가사를 고쳐도 자막만 다시 입히면 돼요.

## 어떻게 만들어지나요? (7단계)

| 단계 | 하는 일 | 담당 |
|---|---|---|
| 1. 노래·가사 | 올린 노래(mp3/wav/m4a/mp4)의 길이·**BPM·박자·마디 자동 분석**, 가사 읽기(Suno 구간 태그, .lrc/.srt 지원) | 내 PC (무료) |
| 2. 기획 | 시리즈 약속(그림체·세계관) + **지난 에피소드 요약**을 읽고 이번 이야기(스토리보드)를 씀. 주인공 이름·모습은 바꾸지 못함 | 구독 LLM |
| 3. 컷 나누기 | 가사 자막 시간 맞추기(탭 또는 자동/가사 파일 시간), **박자 위에서만** 컷 나누기, 후렴·센 마디를 ⭐하이라이트로 | 내 PC |
| 4. 타임시트 | **LLM 이 타임시트(X-sheet)를 짬**: 움직일 컷·멈출 컷, 컷마다 배경 판과 인물 셀(영어), 그림마다 보여 줄 프레임 수(24fps), 카메라, 효과. **PC 가 검사·정리**: 프레임 합계 = 컷 길이, 열쇠 그림 4·3프레임, 그림 장수 예산, 망가진 JSON 고치기. 그릴 장수·시간 **예상**을 보여 주고 멈춤 | 구독 LLM + 내 PC |
| 5. 그림 | 배경 판(인물 없이) + 인물 셀(단색 배경 → **PC 가 배경 빼기·색 맞추기**). **캐릭터 기준 그림 + 고정 설명 + 색 + 규칙**을 매번 함께 보내고, 같은 컷의 다음 그림은 **앞 셀을 첫 번째로 붙여 "이것만 조금 고쳐 줘"** 로 부탁 | ChatGPT 그림(Codex) / Grok Imagine / Gemini 웹 / 도우미 |
| 6. 렌더링 | **PC 가 사이 그림(RIFE/ffmpeg)을 만들고 타임시트대로 렌더링**: 배경·인물을 겹치고(멀티플레인) 그림을 프레임 수만큼 보여 주며 카메라를 움직이고 화면전환·필름 느낌·노래를 입혀 **자막 없는 깨끗한 원본** | 내 PC (무료, 프로그램 안에 포함) |
| 7. 자막 | 깨끗한 원본 위에 가사 자막을 입혀 완성본 + SRT/LRC | 내 PC (무료) |

영상 길이 = 올린 노래 길이입니다. 노래는 Suno 등에서 따로 만들어 올립니다(이 앱은 노래를 만들지 않습니다).

### 렌더링 프로그램을 따로 설치해야 하나요?

**아니요.** 렌더링 합성기(그림 넘기기·배경과 인물 겹치기·카메라 움직임·효과)와 배경 빼기는 이 프로그램 안에 들어 있는 자체 코드이고, 그림 읽기·화면전환·압축에 쓰는 **FFmpeg**,
사이 그림을 만드는 **RIFE**(rife-ncnn-vulkan)도 **설치 파일 안에 함께 들어 있어요**. 설치 파일 하나만 설치하면 됩니다.

## 움직임 방식: 지브리식 · 전체 움직임 · 리미티드

워크플로우의 **[🏃 움직임 방식]** 에서 골라요.

| 방식 | 어떻게 | 그림 장수 (3분 노래 예) | 언제 |
|---|---|---|---|
| 🌿 **지브리식** (기본) | 노래의 40~50% (하이라이트 → 센 컷 순)만 1초에 6장(또는 8장) + 사이 그림, 나머지는 멈춘 그림 1~4장 + 카메라 | 약 500~650장 | 손그림 극장 애니 느낌을 원할 때 |
| 🏃 **전체 움직임** | 모든 컷이 1초에 6~8장 + 사이 그림 | 약 1,100장 이상 | 짧은 노래, 시간이 넉넉할 때 |
| 🖼 **리미티드** | 컷마다 그림 몇 장 + 카메라, 하이라이트는 2프레임씩 (V2 처음 방식) | 약 70~90장 | 빨리, 적게 그리고 싶을 때 |

- **열쇠 그림과 사이 그림**: 움직이는 컷은 AI 가 1초에 6장(그림마다 4프레임) 또는 8장(3프레임) 그려요. 이웃한 두 열쇠 그림 A·B 사이에 **내 PC 가 가운데 그림 한 장**을 만들어서, A 를 앞 절반, 가운데 그림을 뒤 절반 보여 줘요(손그림처럼 2프레임씩). 24프레임을 전부 매끈하게 채우지 않아서 손그림 느낌이 남아요.
- **사이 그림 엔진**: `자동`(기본) = 설치 파일에 든 **RIFE** 를 먼저 쓰고(그래픽카드 → 안 되면 CPU), 안 되면 **ffmpeg** 로 대신해요. 두 그림이 너무 다르면(자세·크기·위치가 크게 바뀜) 사이 그림 없이 그대로 넘겨요. 어떤 엔진을 썼는지 진행 기록에 나와요.
- **작은 변화로 부탁하기**: 타임시트 AI 에게 "열쇠 그림마다 아주 조금씩만 바꾸라"고 하고, 그림 AI 에게는 **앞 셀을 첫 번째로 붙이고** "이 그림에서 이것만 고쳐 줘(디자인·선·색·크기·위치는 그대로)" 로 부탁해요. 걷기·달리기·손 흔들기처럼 반복되는 동작은 4~8장을 돌려 써서(사이클) 장수를 아껴요.
- **배경 빼기**: 인물 셀은 아주 평평한 **초록(#00FF00)** 배경으로 그리게 하고(캐릭터 색에 초록이 있으면 **마젠타 #FF00FF**), PC 가 가장자리 색을 기준으로 이어진 배경만 지워요(눈동자처럼 인물 안의 초록은 남김). 경계는 부드럽게, 초록 번짐은 지우고, 같은 컷 첫 셀에 맞춰 색을 60% 정도 맞춰서 깜빡임을 줄여요. 배경을 뺄 수 없는 그림은 그냥 전체 그림으로 써요.
- **시간과 한도**: 그림 한 장에 30초쯤 걸린다고 치면 지브리식 3분 노래는 **4~5시간**, 리미티드는 30~45분이에요. 구독 사용량 한도에 걸리면 앱이 기다렸다가 이어서 해요. 그래서 그림을 그리기 전에 **"그림 약 N장 (배경 M장 + 인물 K장), 예상 약 H시간"** 을 보여 주고 멈춰요. 너무 많으면 리미티드로 바꾸거나 그림 장수 예산(상한선)을 적어 주세요.
- 지시문에는 회사·작품 이름을 쓰지 않고 "손으로 그린 셀 애니, 수채화 배경" 처럼 **느낌을 설명하는 말**만 써요.

## 주인공 고정: 캐릭터 파일 (.amchar)

- **[🧒 캐릭터]** 화면에서 이름·성격을 적고, 생김새를 한국어로 적은 뒤 **[✨ AI 로 영어 설명 만들기]** 를 누르면 그림 AI 가 잘 알아듣는 영어 고정 설명(얼굴·머리·눈·몸·옷·소품), **색 팔레트(정확한 색 번호)**, **규칙**("늘 빨간 목도리", "머리색 절대 바꾸지 않기")을 만들어 줘요.
- **기준 그림**: 직접 그린 그림을 넣거나, AI 에게 **앞·옆·뒤 모습(턴어라운드) → 표정 모음 → 전신** 순서로 그리게 해요. (턴어라운드를 먼저 그리면 나머지는 그 그림을 보고 똑같이 그려요)
- **[🔒 잠그기]** 를 하면 생김새·색·규칙·기준 그림이 고정돼요. 잠근 캐릭터만 시리즈의 주인공이 될 수 있어요. (잠금을 풀었다 다시 잠그면 버전이 올라가고, 지난 에피소드는 예전 모습 그대로 남아요)
- **.amchar 파일** 하나에 설명·색·규칙·기준 그림(1~6장)이 모두 들어 있어서 다른 PC 나 친구에게 그대로 옮길 수 있어요.

그림을 그릴 때마다 이렇게 보내요:
1. 컷에 나오는 주인공의 기준 그림(턴어라운드·표정·전신)을 첨부 (ChatGPT 는 `--image` 로 직접 첨부, 다른 AI 는 작업 폴더에 복사해서 알려 줌, 도우미 모드는 화면에 보여 줌)
2. 같은 컷의 바로 앞 그림도 첨부 (배경·구도·선 느낌을 이어 가고 자세만 바꾸게)
3. 고정 설명·색 팔레트·규칙을 **글자 그대로** 프롬프트에 넣고, "기준 그림과 똑같이, 다시 디자인하지 말 것" 지시를 강하게 붙임

## 시리즈와 에피소드

- **[📺 시리즈]**: 고정 주인공(캐릭터) + 그림체 약속(예: 80~90년대 손그림 셀 애니, 수채화 배경) + 세계관·분위기 + 에피소드 기록.
- 새 작업 = 시리즈의 **새 에피소드**(EP1, EP2 …). 기획 AI 는 시리즈 약속과 **지난 에피소드 요약**을 읽고 이야기를 이어 가요.
- 에피소드가 완성되면 2~3줄 요약이 시리즈 기록에 남아요. 요약은 직접 고칠 수 있어요.
- 에피소드를 시작할 때 캐릭터 기준 그림을 작업 폴더에 복사해 두어서, 나중에 캐릭터를 바꿔도 지난 에피소드는 그대로 다시 만들 수 있어요.

|---|---|---|
| ChatGPT Plus/Pro/Business | Codex CLI (`codex`) | 기획·타임시트, 그림(`$imagegen`, gpt-image, **기준 그림 직접 첨부**) |
| SuperGrok / X Premium+ | Grok Build CLI (`grok`) | 기획·타임시트, 그림(image_gen) |
| Google AI Pro/Ultra | Antigravity CLI (`agy`) | 기획·타임시트 (그림은 Gemini 웹: 도우미/자동 클릭) |
| Claude Pro/Max | Claude Code (`claude`) | 기획·타임시트 |

웹에서만 되는 그림(예: Gemini 나노바나나)은 두 가지 방법으로 처리합니다.

- **도우미 모드 (기본)**: 앱이 프롬프트와 **기준 그림**을 보여 주고 사이트를 열어 줍니다. 사용자가 그리고 **다운로드만 하면** 다운로드 폴더를 지켜보다가 자동으로 가져옵니다.
- **자동 클릭 (실험적, 기본 꺼짐)**: PC 의 Edge/Chrome 을 전용 프로필로 열어 사람 속도로 대신 누릅니다. 로그인은 사용자가 그 창에서 직접 한 번 합니다.
  - ⚠ 대부분의 AI 서비스 약관은 자동화된 방식의 이용을 금지·제한합니다. **계정 제한 위험이 있고 책임은 사용자에게 있습니다.** 켤 때 동의 창이 뜹니다.
  - CAPTCHA 를 풀거나 봇 탐지를 우회하는 기능은 넣지 않았습니다. 막히면 그 그림만 도우미 모드로 넘어갑니다.

### 그림 장수 예산 (구독 한도 지키기)

워크플로우의 **그림 장수 예산**이 한 에피소드에서 그리는 그림(배경 판 + 인물 셀)의 상한선이에요. 기본은 자동: 움직이는 컷 초 × 1초 장수(6·8) + 멈춘 컷 1~4장 + 컷마다 배경 1장 (리미티드는 3분 노래 ≈ 68장 + 배경).
예산이 모자라면 멈춘 컷 → 움직이는 컷의 열쇠 그림 순서로 줄이고, 그래도 넘치면 덜 중요한 움직이는 컷부터 멈춘 그림 + 카메라로 바꿔요. 컷 수는 3~4분 노래 기준이고, 3분보다 짧은 노래는 길이에 맞춰 줄여요.

## 설치 (Windows 10/11)

1. GitHub 저장소의 **Actions → "AnimeMaker V2 Windows 설치 파일 만들기" → 가장 최근 실행 → Artifacts → `AnimeMaker-V2-Windows`** 를 내려받아 압축을 풉니다.
   (태그 `v2.0.0` 처럼 릴리스를 만들면 **Releases** 에도 올라갑니다.)
2. `AnimeMaker-V2-…-setup.exe`(설치형) 또는 `AnimeMaker-V2-…-portable.exe`(설치 없이 실행)를 실행합니다.
3. "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행** 을 누릅니다. (코드 서명이 없는 개인 프로그램이라 뜨는 안내입니다)

## 처음 사용하기

1. 첫 화면에서 **[체험 모드로 먼저 구경하기]** → 체험용 주인공 "하루" 와 시리즈가 바로 생겨요. 노래 없이 시작하면 예시 노래와 가짜 그림으로 7단계 전체를 볼 수 있어요. (무료)
2. **[AI 연결 설정]** 에서 가진 구독 카드의 **[설치하기] → [로그인 하기] → [연결 테스트]** 를 차례로 누릅니다.
   - Codex 는 OpenAI 공식 설치 프로그램으로 설치해요(Node.js 필요 없음). 예전에 npm 으로 설치한 Codex 도 그대로 찾아요. 로그인 창에서 **"Sign in with ChatGPT"** 를 고르세요. (API key 로그인은 종량제)
   - 같은 화면의 **빠른 설정**에서 내 구독 조합(예: ⭐ ChatGPT 하나로)을 누릅니다.
3. **[🧒 캐릭터]** 에서 주인공을 만들고 기준 그림을 넣고 **🔒 잠그기**.
4. **[📺 시리즈]** 에서 시리즈를 만들고 주인공과 그림체를 고릅니다.
5. **[🎬 새 에피소드 만들기]** 에서 ① 시리즈 → ② 노래 → ③ 가사(붙여넣기 또는 .txt/.lrc/.srt) → ④ 이번 이야기(선택) → ⑤ 워크플로우 → **[▶ 만들기 시작]**.
6. 가사에 시간이 없으면 **"⌨ 가사 자막 시간 맞추기"** 카드가 떠요. 노래를 들으며 줄마다 스페이스바를 누르면 자막과 컷이 가사에 딱 맞습니다. (건너뛰면 자동 추정)

### 다듬기

- **타임시트**: [📋 타임시트] 탭에서 컷마다 그림·노출 띠(X-sheet)·카메라·효과를 봐요. 그림 한 장의 **프레임 수를 바꾸거나**(컷 길이는 그대로, 다음 칸이 맞춰짐) **카메라 움직임**을 바꾸고, **▶ 넘겨보기**로 배경 위에 인물 셀(사이 그림 포함)을 미리 넘겨 볼 수 있어요. 움직이는 컷에는 `🏃 움직임: 1초 6장 + 사이 그림` 표시와 사이 그림 장수·엔진이 나와요. 인물 셀은 체크무늬(= 투명) 위에 보여요.
- **그림 한 장만 다시**: [✏️ 다시](프롬프트 수정 가능) 또는 [📁 교체] → **[🎬 다시 렌더링]** 은 바뀐 컷만 새로 만들어요.
- **가사·자막만 고치기**: 가사를 고치거나 탭으로 다시 맞추면 **[💬 자막만 다시 입히기]** — 그림·렌더링은 그대로.
- **BPM 이 두 배/절반으로 잡힘**: [노래·가사·컷] 탭에서 BPM 을 고치고 다시 분석.
- 이어서 하기, 중지, 구독 한도 대기, 앱이 꺼진 뒤 이어서 하기는 V1 과 같아요.

## 안드로이드 앱 (폰에서 만들기)

컴퓨터 없이 폰 하나로 같은 흐름을 따라 하는 앱이에요 (`mobile/` 폴더, Capacitor + 웹 화면). 앱 이름은 **AnimeMaker V2**, 앱 번호는 `com.animemaker.v2` 라서
V1 안드로이드 앱(`com.animemaker.mobile`)과 따로 설치돼요 — 아이콘(하늘색 → 보라, "V2" 딱지)과 저장 공간도 서로 달라요.
안드로이드 7 이상, 영상은 폰 안에서 만들어요. Android System WebView(또는 Chrome)가 최신일수록 좋고, 앱 시작 화면의 **📱 내 폰 점검** 카드가 이 폰이 영상을 만들 수 있는지(영상·소리 부품, 메모리, 저장 공간)를 알려 주고 고치는 방법도 말해 줘요.

🔒 폰 앱도 **구독 전용**이에요. 유료 API 를 부르지 않고, 폰에 깔린 ChatGPT · Gemini · Grok · Claude 앱으로 글·그림을 주고받기만 해요.

🚧 **지금은 뼈대 단계예요.** 앱 틀(시작 화면 · 설정 · 내 폰 점검 · 공유로 받은 함 · 뒤로가기 안전장치 · 서명 · 자동 빌드)이 준비됐고, 영상을 만드는 화면은 이어서 채워 넣는 중이에요.

**설치**
1. GitHub 저장소의 **Actions → 가장 최근 실행 → Artifacts → `AnimeMaker-V2-Android`** 를 내려받아 압축을 풀면 `AnimeMaker-V2-<버전>-android.apk` 가 나와요. (태그 `v2.0.0` 처럼 릴리스를 만들면 **Releases** 에도 올라가요.)
2. APK 를 폰에서 열고, "출처를 알 수 없는 앱 설치 허용" 을 한 번 켠 뒤 설치해요.
3. **업데이트**는 새 APK 를 그냥 위에 설치하면 돼요. 모든 APK 를 같은 서명 키(`mobile/android/keystore/animemaker-v2.keystore`)로 서명하기 때문이에요.
   ⚠ **이 키 파일을 지우거나 새로 만들면 위에 덮어 설치가 안 돼요.** 앱을 지우고 다시 깔아야 하는데, 그러면 **앱 안에 저장된 작품·캐릭터가 모두 사라져요.** 자세한 내용과 비밀번호·인증서 지문은 [`mobile/android/README-signing.md`](mobile/android/README-signing.md) 에 있어요. (개인 설치용 키라서 저장소에 넣어 두었어요. 여러 사람에게 나눠 줄 때는 비밀 키로 바꾸세요.)

**데이터**: 작품·캐릭터·그림은 이 앱 안(앱 저장소)에만 있어요. 앱을 지우거나 폰 저장 공간이 모자라면 사라질 수 있으니 **완성한 영상은 갤러리(동영상 › AnimeMaker V2)에 저장**해 두세요. 자동 백업은 일부만 복원되는 사고를 막으려고 꺼 두었어요.

**버전 번호**: 앱 버전(`versionName`)은 `mobile/package.json` 의 `version` 하나에서 읽고, 업데이트 설치용 `versionCode` 는 CI 실행 번호가 들어가요. 로컬에서 빌드하면 `versionCode` 가 `1` 이라서, CI 가 만든 APK 위에는 `adb install -r -d` 로만 덮어 설치할 수 있어요.

**직접 빌드** (JDK 21, Android SDK 36, Node 22):
```bash
cd mobile
npm ci
npm test       # 계산 단위 시험 + 공용 코드 번들 가드 + Chromium(412×915)으로 화면 확인 (CHROME_PATH 로 브라우저 지정 가능)
npm run apk    # 배포용 묶음(www/) → cap sync → ./gradlew assembleRelease → android/app/build/outputs/apk/release/app-release.apk (서명됨)
```
개발용 묶음(`npm run build:dev` → `www-dev/`)은 시험 전용이라서, 시험 직후 `cap sync` 를 해도 개발용 묶음이 앱에 들어가지 않아요. 공용 코드는 데스크톱과 **같은 파일**(`scripts/shared-modules.js` 목록)을 esbuild 로 묶어서 써요.
CI 의 `android-apk` 작업이 같은 일을 하고, APK 의 앱 번호·이름·서명 지문까지 확인한 뒤 올려요 (실제 폰에서 돌려 본 것은 아직 아니에요).

```

  src/ui.js, jobs.js    화면 부품(아래 창 · 그만둘 수 있는 기다림 덮개) · 오래 걸리는 일 지킴이(runJob)
```

### 타임시트(X-sheet) 모양 (LLM 이 돌려주는 JSON)

```json
{"shots": [{
  "shot": 3, "motion": true, "highlight": true, "characters": ["하루"],
  "scene_en": "rooftops in the rain at night", "framing_en": "medium shot, low angle",
  "bg": {"prompt_en": "wet rooftops at night, glowing windows, no people"},
  "drawings": [{"id": "A", "prompt_en": "Haru leaps, scarf streaming"}, {"id": "B", "prompt_en": "... (a small change from A)"}],
  "exposure": [{"drawing": "A", "frames": 4}, {"drawing": "B", "frames": 4}, {"cycle": ["A","B","C","D"], "each": 4, "repeat": 6}],
  "camera": {"move": "truck_in", "start": {"zoom": 1.0, "x": 0, "y": 0}, "end": {"zoom": 1.45, "x": 0, "y": -0.15}, "ease": "inout"},
  "fx": ["sparkle"], "transition_out": {"type": "dissolve", "beats": 1}
}]}
```

- 카메라: `hold`, `pan_left/right/up/down`, `zoom_in/out`, `truck_in/out`, `shake`. 구도 `zoom` 1.0(그림 전체)~1.6, `x`·`y` -1~1(그림 안에서 보는 위치).
- 효과: `fade_in`, `fade_out`, `flash`, `sparkle`, `shake`, `dissolve_in`.
- `motion`: 움직이는 컷이면 열쇠 그림마다 정확히 4프레임(1초 6장) 또는 3프레임(1초 8장). PC 가 이웃한 열쇠 그림 사이에 사이 그림을 넣어요. 멈춘 컷은 그림 1~4장을 길게.
- `bg`: 컷의 배경 판(인물 없이). `drawings` 는 인물 셀(인물만, 단색 배경).
- PC 가 정리한 뒤에는 컷마다 `frames`(정확한 프레임 수), `startFrame`, 화면전환 `frames`(짝수, 앞뒤 컷이 반씩 겹침)가 붙고, 전체에 `mode`·`keyRate`·`layers`·`keyColor`·`estimate`(그림 장수·시간 예상)가 붙어요.

서드파티 구성요소는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) 를 참고하세요.
